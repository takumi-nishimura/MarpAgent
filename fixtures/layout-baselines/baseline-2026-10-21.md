## 縦長図の調整試行

基準を保存した後，6ページ目の画像一要素だけを変えた．図・数値・単位・caption・留保・列比率は削除せず，前後の5／7ページも再確認した．CLI の trial は14ページ全体を再検証し，制御済み E2E は同じ DOM 変更の画像と対象・隣接ページの audit を保存する．同じ条件の試行比較は E2E 側を用いる．

| 段階 | 指定の量と理由 | 結果・保持判断 | 保存した原稿・画像 |
| --- | --- | --- | --- |
| 既定 | ページ固有 CSS／inline 指定0．自然寸法で何が起きるかを観察 | 280×640px．lab で最大86pxの欠け | [基準原稿](baseline/slide.md.txt)／[基準画像](baseline/lab/columns-portrait.png) |
| 既存 utility | 画像一要素に `max-h-full` 一つを追加．既存の少数指定で親領域に収まるか試す | 高さを制限する親がないため280×640pxのまま．3テーマとも欠けが残る．この指定は保持しない | [差分](baseline/adjustments/utility.patch)／[原稿](baseline/adjustments/utility-slide.md.txt)／[画像](baseline/lab/trial-utility-portrait.png)／[CLI 検査](baseline/adjustments/utility-validation.json) |
| 画像の寸法指定 | 画像一要素に `max-height: 480px` 一宣言．captionと下端余白を残すための明示上限 | 210×480pxとなり3テーマとも audit の欠け0．CLI も measured／Findings 0／終了0．元24pxの図内文字は表示上約18pxになり，縮小の代償がある．局所的な修正候補として記録し，基準 fixture 自体は変更しない | [差分](baseline/adjustments/inline.patch)／[原稿](baseline/adjustments/inline-slide.md.txt)／[画像](baseline/lab/trial-inline-portrait.png)／[CLI 検査](baseline/adjustments/inline-validation.json) |

最終画像では欠けていた入力条件とcaptionを確認できる．同じ lead の1280×720画像上での確認に限り，投影距離での十分な可読性や，共有 CSS で個別上限が不要になることは実証していない．

基準の調整台帳は次のとおりである．ロゴ無効化の `section` 一ルール・二宣言は環境制御として一度だけ数える．5／6ページは配置 wrapper 3要素ずつを8:4の関係のために保持し，7／8ページは縦積み wrapper 1要素ずつを読む順序のために保持する．`figure`／`figcaption`，出典の `.footnote` は意味・既存部品の構造として分ける．ページ固有の scoped CSS，inline 寸法指定，意図した crop／scroll は基準にはない．少ない行数を目標に情報を減らす比較は行っていない．

## 実行したチェックと限界

```sh
node --test --test-reporter=spec tests/unit/layout-baselines.test.js tests/unit/theme-css.test.js tests/unit/marp-engine.test.js
FONTCONFIG_FILE=/tmp/marp-i54-baseline/fonts.conf flock /tmp/marpagent-parallel-20261021/browser-tests.lock npm run test:e2e -- tests/e2e/composition-utilities.spec.js --project=chromium --workers=1
FONTCONFIG_FILE=/tmp/marp-i54-baseline/fonts.conf flock /tmp/marpagent-parallel-20261021/browser-tests.lock npm run marpx -- fixtures/layout-baselines/slide.md -v --strict --report-dir out/layout-baseline-20261021/validation
FONTCONFIG_FILE=/tmp/marp-i54-baseline/fonts.conf flock /tmp/marpagent-parallel-20261021/browser-tests.lock npm run marpx -- fixtures/layout-baselines/slide.md --images png --output out/layout-baseline-20261021/slides.png
```

unit／テーマ整合／configured engine の対象32件と composition E2E 9件は成功した．CLI 子プロセスを含む unit は sandbox 内の詳細なし失敗後，通常のローカル実行条件で再確認した．意図した欠けを含む基準 validator の終了1は上記の測定結果として残す．新しい CI や評価サービスは追加していない．

既存の対照例も同じ Fontconfig で strict validator を実行した．[overflow](baseline/controls/overflow.json) は measured／`content-clipped` 最大194px／`edge-crowding`／終了1，[脚注衝突](baseline/controls/text-overlap.json) は measured／`text-overlap` 最大11px／終了1だった．それぞれ画像も `controls/` に残した．期待した失敗であり，この fixture の「未修正エラー数」に混ぜない．

slide-edit／slide-review には既定動作→既存パラメータ・utility→必要なページ固有 CSS，内容・色付き強調の保持，影響ページと隣接ページの再確認，領域と理由を持つ視覚記録を反映した．ローカルリンクは解決した．skill-creator の `quick_validate.py` は両 skill の既存 `argument-hint` を未対応キーとして拒否する．変更前の `119fbbb` でも同じ結果を確認し，frontmatterは変更していない．この検査を成功とは報告しない．

Firefox，PDF／PPTX，紙面／scroll，投影による読取，内容理解の実験は未実施．共有 CSS を変更していないため，本担当では統合 full strict gate を回さず，main の統合確認に委ねる．後続の #55／#57 は同じ入力とブラウザ・フォント条件を使い，採用した指定・撤去した指定・残した理由を新しい run に記録する．
